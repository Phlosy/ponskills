# Gate 0: Core Claim Skeleton, Slide Outline & Data Basis Review Protocol (`⛔ BLOCKING GATE 0：核心论点骨架、逐页大纲概要与数据依据审阅门禁`)

## 1. Hard Blocking Discipline (`⛔ BLOCKING 门禁强制暂停规则`)

A common failure mode in both academic report writing and presentation PPT preparation is jumping directly into drafting paragraphs, creating templates, or generating slides before aligning with the user on the slide-by-slide outline and core claims.

**`⛔ BLOCKING GATE 0` (`核心论点骨架、逐页大纲与数据依据审阅门禁`)** enforces a strict hard-stop protocol:
1. **Step 0A (Outline & Data Basis Lock)**:
   - Extract the **macro narrative spine**, the **single Core Claim (`唯一核心论点`)** of every section or slide, the **inter-claim logical connectors (`相邻论点串联逻辑`)**, the **adaptive Top/Bottom anchor plan (`顶/底框按需配置方案`)**, the **single Visual Focal Point (`本页唯一视觉重心`)**, and the **planned Figure Modality (`配图形式选型`)**.
   - Whenever public data survey or quantitative calculation is required, compile a standalone **Authoritative Data Sources & Calculation Basis Document (`<题目>_权威数据来源与测算依据.md`)** listing exact official sources (ITU, FCC, 3GPP, peer-reviewed papers, corporate filings) and step-by-step derivation formulas.
2. **Step 0B (`⛔ HARD STOP — 等待用户明确确认`)**:
   - Present the Gate 0 review sheet and data basis document to the user and **STOP IMMEDIATELY**.
   - **Never** proceed to Gate 1 (Master Template creation) or slide generation until the user explicitly replies with confirmation (e.g., `"确认"`, `"大纲没问题，继续"`).

## 2. Five Mandatory Components of the Gate 0 Outline Review Sheet

When presenting the Gate 0 review document (see [`../templates/core_claim_skeleton_template.md`](../templates/core_claim_skeleton_template.md)), include all five components below concisely:

### 2.1 Overarching Core Question (`全篇唯一核心总问题`)
Formulate one overarching sentence that captures:
- **System context & intrinsic constraint** (under what physical/system reality and resource boundary);
- **Paradigm shift** (e.g., moving from single-pipe transmission or open-loop trial-and-error to multi-node value mining or closed-loop inverse solving);
- **Complete closed-loop chain** (mechanism shift $\rightarrow$ core technology $\rightarrow$ verification/platform substrate).

### 2.2 Node-by-Node Single Core Claim & Adaptive Anchor Plan (`逐节/逐页唯一核心论点与顶/底框按需配置`)
For every section (in a report) or every slide (in a PPT):
- **One Core Claim Rule**: Each node may carry **only one core claim**. If a node attempts to argue two distinct points, split it into two consecutive nodes immediately.
- **Adaptive Top/Bottom Anchor Configuration (`顶/底核心框按逻辑按需配置，打破机械双框`)**:
  - Every content slide must retain **at least one** summary bar (Top or Bottom), but **never force both Top and Bottom bars if they say the same thing**:
    - **Single Bar (`仅顶部框` or `仅底部框`)**: Use when the slide presents a single-layer phenomenon, trend, scale calculation, or direct structural comparison.
    - **Dual Bars (`顶部框 + 底部框`)**: Use **only** when the slide has a genuine two-level progression or conceptual pivot (`上表征/正面工程目标 → 下底层规律/思维转折`).
- **Single Visual Focal Point (`本页唯一视觉重心`)**: Specify which card, module, or comparative chart on the slide will be highlighted with the **20% Vibrant Focal Accent Color (`#D9232E` / `#C81E2B` red header & bold red key text)**.
- **Planned Figure Modality (`配图形式选型`)**: Specify whether each visual uses (a) an authentic public photo/rendering, (b) a pure geometric vector schematic (e.g., for upright vs. inverted cone symmetry), (c) a multi-element realistic scene composite, or (d) an equidistant quantitative chart.

### 2.3 Explicit Inter-Claim Connectors (`相邻论点间的必然串联逻辑`)
Between Node $k$ and Node $k+1$, write a one-line connector explaining **why Node $k$ inevitably leads to Node $k+1$**:
- **Causal Connector (`因果传导`)**: Node $k$ establishes structural/scale leap $X$ $\Longrightarrow$ Node $k+1$ shows how $X$ reshapes design boundaries or induces paradigm shift $Y$.
- **Contrastive Bridge (`对比桥梁`)**: Insert comparison nodes so the audience understands why legacy architectures behave differently from the target system.
- **Summary-to-Survey Bridge (`承上启下问题汇总桥`)**: When transitioning from "Problem Formulation" to "Related Work", summarize the core problems and map each problem 1-to-1 to an existing literature stream.

### 2.4 Horizontal Decomposition & Indispensability Proof (`核心问题的必然拆解与缺一不可关系`)
When decomposing the overarching problem or system into $K$ research contents or simulation domains, explicitly explain:
1. **Why these $K$ parts (`必然拆解逻辑`)**: Why solving the overarching problem requires decomposing into Part 1, Part 2, ..., Part $K$.
2. **Why none can be omitted (`缺一不可证明`)**: How their forward data dependency and closed-loop coupling bind all $K$ parts into an inseparable whole.

### 2.5 Authoritative Data Basis Verification (`独立数据来源与测算依据文档`)
- All quantitative numbers and projections shown on slides must be documented in `<题目>_权威数据来源与测算依据.md` with real citations and derivation steps, while keeping the PPT slide canvas clean of cluttered citation footnotes.
- Distinguish strictly between **sourced quantitative metrics** (display exact numbers on the slide) and **qualitative conceptual comparisons** (hide unverified percentage numbers on the slide, showing proportional bars and qualitative labels instead).

---

## 3. Gate 0 Verification Checklist

Before pausing for user confirmation at `⛔ BLOCKING GATE 0`, verify:
- [ ] Does every slide/section have **exactly one** core claim and **one** clearly designated Visual Focal Point (`视觉重心`)?
- [ ] Is the Top/Bottom anchor configuration adaptive (using a single bar when expressing one layer of meaning, and dual bars only when a two-level pivot exists)?
- [ ] Are tag labels rigorous and free of sensationalism or misapplied `"本质矛盾"` labels?
- [ ] Has `<题目>_权威数据来源与测算依据.md` been created and cross-checked for equidistant time scales and authentic sources?
- [ ] Have you explicitly stopped to wait for user confirmation before entering `⛔ BLOCKING GATE 1`?
